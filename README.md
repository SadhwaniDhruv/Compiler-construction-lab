# Compiler Design Labs: Flex/LEX and Bison/YACC

A runnable Ubuntu lab set for the 10 practicals and the value-added intermediate-code generator. The source is split by experiment; `Makefile` builds every program into `bin/` and keeps generated C/header files in `build/` (both are ignored by Git).

## 1. Install tools (Ubuntu)

Run these commands in a terminal:

```bash
sudo apt update
sudo apt install -y flex bison build-essential make git gh
```

Check the tools:

```bash
flex --version
bison --version
gcc --version
gh --version
```

`gh` is the GitHub CLI. If Ubuntu says it cannot find package `gh`, install it using GitHub's official CLI installation instructions, then continue.

## 2. Enter the project and compile

If you are using the prepared Manus Ubuntu workspace:

```bash
cd /home/ubuntu/compiler-construction-lab
```

If you downloaded or cloned this project elsewhere, `cd` to that project folder instead. Build all eleven executables:

```bash
make clean
make
```

Run the automatic smoke tests:

```bash
make test
```

Success ends with `All 11 practical smoke tests passed.` `make clean` removes generated files only; it does not delete the `.l`, `.y`, sample, or documentation sources.

## 3. Run each practical

Run commands from the project root. `<` feeds a sample file to a program's standard input; `>` redirects generated output into a file.

| Practical | What it demonstrates | Run command |
|---|---|---|
| 1 | Flex definitions/rules/user-code sections; keywords, identifiers, numbers, operators, punctuation, and comments | `./bin/practical01 < samples/p01.txt` |
| 2 | Counts comments, keywords, identifier-shaped words, total words, physical lines, and spaces/tabs | `./bin/practical02 < samples/p02.c` |
| 3 | Counts alphabetic words beginning with A/a and numbers in scientific notation (`e`/`E`) | `./bin/practical03 < samples/p03.txt` |
| 4 | Introductory Bison/Yacc grammar, semantic values, precedence, and arithmetic evaluation | `./bin/practical04 < samples/p04.txt` |
| 5 | Converts letters in either direction; punctuation and whitespace are preserved | `./bin/practical05 --upper < samples/p05.txt` or `./bin/practical05 --lower < samples/p05.txt` |
| 6 | Reads a named file, converts each decimal digit sequence to hexadecimal, and preserves other characters | `./bin/practical06 samples/p06.txt` |
| 7 | Prints only input lines whose final text is uppercase `COM` (`.com` and lowercase `com` do not match) | `./bin/practical07 < samples/p07.txt` |
| 8 | Evaluates postfix expressions (Reverse Polish notation), one expression per line | `./bin/practical08 < samples/p08.txt` |
| 9 | Desk calculator with arithmetic precedence, parentheses, unary minus, and recovery at the next line | `./bin/practical09 < samples/p09.txt` |
| 10 | Parses the supported `for (assignment; condition; update) { assignment; ... }` loop subset | `./bin/practical10 < samples/p10.txt` |
| Value added | Emits three-address intermediate code for arithmetic assignments | `./bin/value_added_icg < samples/icg.txt` |

You can type input interactively by running an executable without redirection, then press **Ctrl-D** on an empty line to finish. For example:

```bash
./bin/practical09
(2 + 3) * 4
```

## 4. How the source files are organized

- Each `practicalNN_.../lexer.l` is a Flex scanner. Flex files have a definitions section, a `%%` separator, a rules section, a second `%%`, then optional C code. Each rule pairs a regular-expression pattern with a C action.
- Parser exercises have a `parser.y` Bison grammar as well. A Yacc/Bison source has declarations, `%%`, grammar productions with semantic actions, `%%`, then C helper functions. `lexer.l` includes the generated `parser.tab.h` so both tools agree on token numbers and semantic-value types.
- `samples/` contains reproducible inputs; `tests/run-tests.sh` checks the expected behavior; `Makefile` contains each generation and compile command.
- `build/` and `bin/` are generated by `make` and intentionally are not committed.

### Compile a single Flex-only practical by hand

For example, Practical 1:

```bash
flex -o /tmp/p01.c practical01_lex_intro/lexer.l
gcc -Wall -Wextra /tmp/p01.c -o /tmp/p01
/tmp/p01 < samples/p01.txt
```

### Compile a Flex + Bison practical by hand

For example, Practical 4. Bison must create its token header before Flex compiles the scanner:

```bash
mkdir -p /tmp/p04
bison -d -o /tmp/p04/parser.tab.c practical04_yacc_intro/parser.y
flex -o /tmp/p04/lexer.c practical04_yacc_intro/lexer.l
gcc -Wall -Wextra -I/tmp/p04 /tmp/p04/parser.tab.c /tmp/p04/lexer.c -o /tmp/p04/practical04
/tmp/p04/practical04 < samples/p04.txt
```

## 5. Push the project to a new public GitHub repository from the terminal

The intended repository name is **`compiler-construction-lab`** and the visibility is **public**, as selected for this project. Make sure the source tree contains no passwords, API tokens, private keys, or other private files before publishing.

1. Sign in to GitHub from the terminal (the CLI displays a one-time browser verification code; enter it only on GitHub's official device-login page):

   ```bash
   gh auth login --hostname github.com --git-protocol https --web
   gh auth status
   ```

2. Set a commit author for this repository, then initialize and review what will be committed. Replace the two examples with the name and email you want shown in Git history:

   ```bash
   cd /home/ubuntu/compiler-construction-lab
   git init -b main
   git config user.name "Your Name"
   git config user.email "you@example.com"
   git add .
   git status --short
   ```

3. Commit the files and create the public GitHub repository while pushing the `main` branch:

   ```bash
   git commit -m "Add Flex and Bison compiler design practicals"
   gh repo create compiler-construction-lab --public --source=. --remote=origin --push
   ```

4. Verify the remote and published repository:

   ```bash
   git remote -v
   git status --short --branch
   gh repo view --web
   ```

If the repository already exists, do not run `gh repo create`; add its URL as `origin` (`git remote add origin https://github.com/USER/REPO.git`) and use `git push -u origin main` instead. Replace `USER/REPO` with the actual path.

## Learning notes / scope

These are small teaching examples rather than production compilers. Practical 2 defines a “word” as an identifier-shaped token outside comments and counts spaces/tabs even inside comments. Practical 3 treats A/a alike and recognizes decimal scientific notation. Practical 6 converts unsigned decimal integer runs that fit in `unsigned long long`. Practical 7 is deliberately case-sensitive. Practical 10 accepts a useful but intentionally limited FOR-loop grammar (assignment init, comparison condition, simple assignment or increment/decrement update, and assignment statements in the body); it does not execute the loop or implement all of C. The ICG emits temporary names in reduction order and demonstrates precedence, not machine code.
